System Architecture & ER Diagram

Module 01 • Central Identity
USERS & VERIFICATIONS
  • user_id (PK, UUID)
  • email (Unique login)
  • auth_provider (LOCAL / GOOGLE OAuth)
  • role (PATIENT / DOCTOR)
  • USER_VERIFICATIONS (OTP codes, 1:N)
↓ Extends via 1 : 1 Unique Foreign Key ↓
Module 02 • Healthcare Profile
PATIENTS (1:1)
  • patient_id (PK, UUID)
  • user_id (FK • 1:1 with USERS)
  • first_name, last_name
  • date_of_birth, gender
  • blood_group, emergency_contact
Module 03 • Clinical Credentials
DOCTORS (1:1)
  • doctor_id (PK, UUID)
  • user_id (FK • 1:1 with USERS)
  • specialization (Cardiology, etc.)
  • consultation_fee, qualification
  • rating_avg, total_reviews
↓ Doctor Configures Availability ↓
Module 04 • Parent Shift Block
AVAILABILITY SLOTS (1:N)
  • slot_id (PK, UUID)
  • doctor_id (FK • Doctor ↔ Slot: 1:N)
  • slot_date (Calendar date)
  • start_time • end_time (Shift window)
  • slot_duration_minutes (30 mins)
→ 1:N →
Module 04 • Granular Bookable Units
TIME SLOTS (1:N)
  • time_id (PK, UUID)
  • slot_id (FK • Slot ↔ Time: 1:N)
  • start_time • end_time (e.g. 09:00 - 09:30)
  • status (AVAILABLE, BOOKED, RESERVED)
↓ Patient (N:1) + Doctor (N:1) + TimeSlot (Unique 1:1 Lock) ↓
Module 05 • Core Booking Engine
APPOINTMENTS
  • appointment_id (PK, UUID)
  • patient_id (FK • N:1 with Patients)
  • doctor_id (FK • N:1 with Doctors)
  • time_id (FK • Unique 1:1 Lock • Zero Double-Booking)
  • appointment_date, status (CONFIRMED, CANCELLED)
Module 05 • Week 3 Audit
RESCHEDULE HISTORIES (1:N)
  • reschedule_id (PK, UUID)
  • appointment_id (FK • 1:N)
  • old_time_id • new_time_id
  • reschedule_reason, rescheduled_by
Module 05 • System Alerts
NOTIFICATIONS (1:N)
  • notification_id (PK, UUID)
  • user_id • appointment_id
  • message: "Your appt with Dr. XYZ is confirmed"
  • type (CONFIRMATION, REMINDER)

Weekly Plan Relationship Requirements Mapping

Relationship Cardinality Weekly Plan Requirement Implementation & Constraint Rationale
Users ↔ Patients 1 : 1 Week 1: Role-based Onboarding (Patient) user_id unique foreign key prevents multiple profiles per user account.
Users ↔ Doctors 1 : 1 Week 1: Role-based Onboarding (Doctor) Decoupled auth credentials from clinical and rating metadata.
Doctor ↔ Slot 1 : N Week 2: Doctor ↔ Slot (1:N) Doctor configures multiple daily shift intervals in doctor_availability_slots.
Slot ↔ Time 1 : N Week 2: Slot ↔ Time (1:N) Parent slot automatically partitions into 30-min bookable rows in time_slots.
Appointment ↔ Patient N : 1 Week 2: Appointment ↔ Patient (N:1) Patients can book multiple consultations over time.
Appointment ↔ Doctor N : 1 Week 2: Appointment ↔ Doctor (N:1) Doctors conduct consultations for multiple patients.
Appointment ↔ Time Slot 1 : 1 Week 2: Booking concurrency lock Unique constraint on time_id eliminates double booking race conditions.
Appointment ↔ RescheduleHistory 1 : N Week 3: Appointment ↔ RescheduleHistory (1:N) Preserves full timeline of previous slot, new slot, reason, and initiator.

PostgreSQL 3NF DDL Schema Preview 

-- PearlThoughts Schedule Project Module (PostgreSQL 3NF)
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) NOT NULL UNIQUE,
    phone VARCHAR(20) UNIQUE,
    password_hash VARCHAR(255),
    role user_role_enum NOT NULL DEFAULT 'PATIENT',
    auth_provider auth_provider_enum NOT NULL DEFAULT 'LOCAL',
    google_id VARCHAR(255) UNIQUE,
    is_verified BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE patients (
    patient_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL UNIQUE REFERENCES users(user_id) ON DELETE CASCADE,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    date_of_birth DATE,
    blood_group VARCHAR(5)
);

CREATE TABLE doctors (
    doctor_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL UNIQUE REFERENCES users(user_id) ON DELETE CASCADE,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    specialization VARCHAR(150) NOT NULL,
    consultation_fee NUMERIC(10, 2) NOT NULL,
    rating_avg NUMERIC(3, 2) NOT NULL DEFAULT 5.00
);

-- Doctor ↔ Slot (1:N) & Slot ↔ Time (1:N)
CREATE TABLE doctor_availability_slots (
    slot_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    doctor_id UUID NOT NULL REFERENCES doctors(doctor_id) ON DELETE CASCADE,
    slot_date DATE NOT NULL,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL
);

CREATE TABLE time_slots (
    time_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    slot_id UUID NOT NULL REFERENCES doctor_availability_slots(slot_id) ON DELETE CASCADE,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    status time_slot_status_enum NOT NULL DEFAULT 'AVAILABLE'
);

-- Appointment ↔ Patient (N:1), Doctor (N:1), TimeSlot (1:1)
CREATE TABLE appointments (
    appointment_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    patient_id UUID NOT NULL REFERENCES patients(patient_id),
    doctor_id UUID NOT NULL REFERENCES doctors(doctor_id),
    time_id UUID NOT NULL UNIQUE REFERENCES time_slots(time_id),
    appointment_date DATE NOT NULL,
    status appointment_status_enum NOT NULL DEFAULT 'CONFIRMED'
);

-- Appointment ↔ RescheduleHistory (1:N)
CREATE TABLE reschedule_histories (
    reschedule_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    appointment_id UUID NOT NULL REFERENCES appointments(appointment_id) ON DELETE CASCADE,
    old_time_id UUID NOT NULL REFERENCES time_slots(time_id),
    new_time_id UUID NOT NULL REFERENCES time_slots(time_id),
    reschedule_reason TEXT,
    rescheduled_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
